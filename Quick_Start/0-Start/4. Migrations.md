# What is Migration?

Migration means:

> “Take my Django Model and create/update the database table.”

You write Python code:

```python
class Product(models.Model):
    name = models.CharField(max_length=100)
    price = models.IntegerField()
```

But the database does **not** automatically know this.

So we use migrations to tell the database:

```text
Create a Product table with:
- id
- name
- price
```

---

# FastAPI comparison

In FastAPI, if you use SQLAlchemy, you may use:

```text
Alembic
```

FastAPI world:

```text
SQLAlchemy Model -> Alembic Migration -> Database Table
```

Django world:

```text
Django Model -> Django Migration -> Database Table
```

So:

```text
Django migrations = Alembic migrations
```

# Two important commands

## 1. makemigrations

```bash
python manage.py makemigrations
```

Meaning:

```text
Django, look at my models.py and prepare migration files.
```

It creates files like:

```text
users/migrations/0001_initial.py
```

This file is like a database-change plan.

---

## 2. migrate

```bash
python manage.py migrate
```

Meaning:

```text
Django, now apply those migration files to the real database.
```

This creates/updates the real database tables.

---

# Easy memory

```text
makemigrations = make the plan

migrate = execute the plan
```

Example:

```text
You want to build a house.

makemigrations = architect draws the plan
migrate = workers build the house
```

# Example step by step

## Step 1: Create model

```python
# products/models.py

from django.db import models

class Product(models.Model):
    name = models.CharField(max_length=100)
    price = models.IntegerField()
```

At this point, only Python code exists.

No database table yet.

---

## Step 2: Make migration

```bash
python manage.py makemigrations
```

Django says something like:

```text
Migrations for 'products':
  products/migrations/0001_initial.py
    - Create model Product
```

Meaning:

```text
Django created a migration file.
```

---

## Step 3: Apply migration

```bash
python manage.py migrate
```

Now Django creates the actual database table.

Database becomes:

| id | name   | price |
| -- | ------ | ----- |
| 1  | Laptop | 50000 |
| 2  | Phone  | 30000 |

---

# Very important

If you only run:

```bash
python manage.py makemigrations
```

database table is **not created yet**.

If you only run:

```bash
python manage.py migrate
```

without making new migrations, Django only applies already existing migration files.

Usually you run both:

```bash
python manage.py makemigrations
python manage.py migrate
```

# What happens if we change model?

Suppose first model was:

```python
class Product(models.Model):
    name = models.CharField(max_length=100)
    price = models.IntegerField()
```

Later you add:

```python
description = models.TextField()
```

Now model is:

```python
class Product(models.Model):
    name = models.CharField(max_length=100)
    price = models.IntegerField()
    description = models.TextField()
```

Again run:

```bash
python manage.py makemigrations
python manage.py migrate
```

Django will update the database table and add the new column.

For **each Django app**, Django creates a separate `migrations` folder.

Example:

```text
project/
│
├── users/
│   ├── models.py
│   └── migrations/
│       └── 0001_initial.py
│
├── products/
│   ├── models.py
│   └── migrations/
│       └── 0001_initial.py
│
├── orders/
│   ├── models.py
│   └── migrations/
│       └── 0001_initial.py
```

But important:

`0001_initial.py` is created only when that app has a model/change.

Example:

```python
class User(models.Model):
    name = models.CharField(max_length=100)
```

Then:

```bash
python manage.py makemigrations
```

creates:

```text
users/migrations/0001_initial.py
```

Easy memory:

```text
Each app has its own models.py
Each app has its own migrations folder
Each app has its own migration files
```

So yes, `users/migrations/0001_initial.py` belongs only to the `users` app.
