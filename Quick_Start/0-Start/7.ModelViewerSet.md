# Topic 6: ViewSets and Routers

This is where **DRF becomes very powerful**.

Until now, we wrote views like this:

```python
class TodoView(APIView):

    def get(self, request):
        ...

    def post(self, request):
        ...
```

That is okay, but for CRUD APIs it becomes long.

---

# 1. What problem do ViewSets solve?

In FastAPI, for CRUD you write many endpoints:

```python
@app.get("/todos/")
def get_todos():
    pass

@app.post("/todos/")
def create_todo():
    pass

@app.get("/todos/{id}")
def get_todo(id: int):
    pass

@app.put("/todos/{id}")
def update_todo(id: int):
    pass

@app.delete("/todos/{id}")
def delete_todo(id: int):
    pass
```

In DRF, instead of writing all manually, we can use:

```python
ModelViewSet
```

It automatically gives CRUD.

---

# 2. DRF ViewSet example

```python
from rest_framework.viewsets import ModelViewSet
from .models import Todo
from .serializers import TodoSerializer

class TodoViewSet(ModelViewSet):
    queryset = Todo.objects.all()
    serializer_class = TodoSerializer
```

This small code gives:

```text
GET     /todos/       -> list all todos
POST    /todos/       -> create todo
GET     /todos/1/     -> get one todo
PUT     /todos/1/     -> update todo
PATCH   /todos/1/     -> partial update todo
DELETE  /todos/1/     -> delete todo
```

This is the “magic” of DRF.

# 6. What is a Router?

With `APIView`, we used:

```python
path("todos/", TodoView.as_view())
```

But with `ViewSet`, we usually use a **Router**.

Router automatically creates URLs for the ViewSet.

```python
from rest_framework.routers import DefaultRouter
from .views import TodoViewSet

router = DefaultRouter()
router.register("todos", TodoViewSet)

urlpatterns = router.urls
```

Now DRF automatically creates:

```text
/todos/
/todos/1/
```

# 9. APIView vs ViewSet

Use `APIView` when you want full manual control:

```python
class TodoView(APIView):
    def get(self, request):
        ...
```

Use `ModelViewSet` when you want fast CRUD:

```python
class TodoViewSet(ModelViewSet):
    queryset = Todo.objects.all()
    serializer_class = TodoSerializer
```

Simple rule:

```text
Custom logic -> APIView
Normal CRUD -> ModelViewSet
```

# 1. How does it know GET, POST, PUT, DELETE?

Because the **Router** connects HTTP method + URL to a built-in action.

```python
router = DefaultRouter()
router.register("todos", TodoViewSet)
```

DRF automatically creates this mapping:

| Request | URL         | DRF Action         |
| ------- | ----------- | ------------------ |
| GET     | `/todos/`   | `list()`           |
| POST    | `/todos/`   | `create()`         |
| GET     | `/todos/1/` | `retrieve()`       |
| PUT     | `/todos/1/` | `update()`         |
| PATCH   | `/todos/1/` | `partial_update()` |
| DELETE  | `/todos/1/` | `destroy()`        |

So this FastAPI code:

```python
@app.get("/todos/")
def list_todos():
    pass

@app.post("/todos/")
def create_todo():
    pass

@app.get("/todos/{id}")
def get_todo(id: int):
    pass

@app.put("/todos/{id}")
def update_todo(id: int):
    pass

@app.delete("/todos/{id}")
def delete_todo(id: int):
    pass
```

is replaced by this in DRF:

```python
class TodoViewSet(ModelViewSet):
    queryset = Todo.objects.all()
    serializer_class = TodoSerializer
```

# 2. How does it know which query to run?

This line:

```python
queryset = Todo.objects.all()
```

means:

> This API works with Todo objects.

So for list:

```text
GET /todos/
```

DRF uses:

```python
Todo.objects.all()
```

For one item:

```text
GET /todos/1/
```

DRF does something like:

```python
Todo.objects.get(id=1)
```

You do not write it manually because `ModelViewSet` already knows normal CRUD behavior.

# 3. What if I want custom query?

Then override `get_queryset()`.

Example: only show completed todos.

```python
class TodoViewSet(ModelViewSet):
    serializer_class = TodoSerializer

    def get_queryset(self):
        return Todo.objects.filter(completed=True)
```

FastAPI comparison:

```python
@app.get("/todos/")
def list_todos():
    return db.query(Todo).filter(Todo.completed == True).all()
```

So:

```text
FastAPI: write query inside function
DRF: write query inside get_queryset()
```

# 4. What about separate input and output serializers?

Excellent question.

By default this:

```python
serializer_class = TodoSerializer
```

uses the same serializer for all actions:

```text
GET output
POST input
PUT input
PATCH input
```

For simple APIs, this is okay.

But in real projects, yes, you may want separate serializers.

Example:

```python
class TodoCreateSerializer(serializers.ModelSerializer):
    class Meta:
        model = Todo
        fields = ["title", "completed"]
```

For input.

```python
class TodoResponseSerializer(serializers.ModelSerializer):
    class Meta:
        model = Todo
        fields = ["id", "title", "completed"]
```

For output.

Then in ViewSet:

```python
class TodoViewSet(ModelViewSet):
    queryset = Todo.objects.all()

    def get_serializer_class(self):
        if self.action == "create":
            return TodoCreateSerializer

        return TodoResponseSerializer
```

Now DRF decides serializer based on action.

---

# 5. What is `self.action`?

DRF gives action names automatically:

| Request            | `self.action`      |
| ------------------ | ------------------ |
| GET `/todos/`      | `"list"`           |
| POST `/todos/`     | `"create"`         |
| GET `/todos/1/`    | `"retrieve"`       |
| PUT `/todos/1/`    | `"update"`         |
| PATCH `/todos/1/`  | `"partial_update"` |
| DELETE `/todos/1/` | `"destroy"`        |

So you can do:

```python
def get_serializer_class(self):
    if self.action == "create":
        return TodoCreateSerializer

    if self.action == "list":
        return TodoResponseSerializer

    return TodoResponseSerializer
```

# 6. Can we customize each CRUD operation?

Yes.

`ModelViewSet` already has these methods:

```python
list()
create()
retrieve()
update()
partial_update()
destroy()
```

You can override them.

Example:

```python
class TodoViewSet(ModelViewSet):
    queryset = Todo.objects.all()
    serializer_class = TodoSerializer

    def list(self, request):
        todos = Todo.objects.all()
        serializer = self.get_serializer(todos, many=True)
        return Response(serializer.data)
```

This is like FastAPI:

```python
@app.get("/todos/")
def list_todos():
    todos = db.query(Todo).all()
    return todos
```

But only override when you need custom behavior.
