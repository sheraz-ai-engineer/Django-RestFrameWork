# Topic: Views

In simple words:

> A **View** is the place where Django handles the request and returns a response.

FastAPI calls this an **endpoint**.

---

## FastAPI example

```python
@app.get("/hello")
def hello():
    return {"message": "Hello"}
```

This means:

```text
When user visits /hello,
run this function,
return response.
```

---

## Django view example

```python
from django.http import JsonResponse

def hello(request):
    return JsonResponse({"message": "Hello"})
```

Same idea.

```text
FastAPI endpoint = Django view
```

---

# Very simple comparison

## FastAPI

```python
@app.get("/users")
def get_users():
    return {"users": ["Ali", "Sara"]}
```

## Django

```python
from django.http import JsonResponse

def get_users(request):
    return JsonResponse({
        "users": ["Ali", "Sara"]
    })
```

Main difference:

Django view usually receives:

```python
request
```

as first argument.

# But in DRF we use DRF views

Plain Django:

```python
from django.http import JsonResponse
```

DRF:

```python
from rest_framework.response import Response

```

Example:

```python
from rest_framework.views import APIView
from rest_framework.response import Response

class HelloView(APIView):

    def get(self, request):

```

This is like FastAPI:

```python
@app.get("/hello")
def hello():

```

# Why class?

In FastAPI you write separate decorators:

```python
@app.get("/users")
def get_users():
    pass

@app.post("/users")
def create_user():
    pass
```

In DRF, we can put both inside one class:

```python
class UserView(APIView):

    def get(self, request):
        return Response({"message": "Get users"})

    def post(self, request):
        return Response({"message": "Create user"})
```

So:

```text
get()  = handles GET request
post() = handles POST request
put()  = handles PUT request
delete() = handles DELETE request
```

| `@app.delete()`        | `def delete()`                   |
| endpoint function      | view method                      |

# Example with Todo

Suppose we have this model:

```python
class Todo(models.Model):
    title = models.CharField(max_length=100)
    completed = models.BooleanField(default=False)
```

And serializer:

```python
class TodoSerializer(serializers.ModelSerializer):
    class Meta:
        model = Todo
        fields = "__all__"
```

Now view:

```python
from rest_framework.views import APIView
from rest_framework.response import Response
from .models import Todo
from .serializers import TodoSerializer

class TodoView(APIView):

    def get(self, request):
        todos = Todo.objects.all()
        serializer = TodoSerializer(todos, many=True)
        return Response(serializer.data)
```

Meaning:

```text
Get all todos from database.
Convert them using serializer.
Return JSON response.
```

FastAPI idea:

```python
@app.get("/todos")
def get_todos():
    todos = db.query(Todo).all()
    return todos
```

---

# Most important line

```python
todos = Todo.objects.all()
```

This means:

```text
Get all Todo rows from database.
```

In FastAPI/SQLAlchemy, similar to:

```python
todos = db.query(Todo).all()
```

---

# Another important line

```python
serializer = TodoSerializer(todos, many=True)
```

This means:

```text
Convert many Todo objects into JSON-friendly data.
```

`many=True` because we have a list of todos.

If only one todo:

```python
serializer = TodoSerializer(todo)
```


# Mini quiz

In DRF:

```python
def get(self, request):
```

handles which HTTP method?

A) POST
B) GET




Yes, exactly. In **FastAPI**, endpoint URL and function are together:

```python
@app.post("/create-user")
def create_user():
    ...
```

In **Django/DRF**, the URL is usually written in a separate file called `urls.py`.

## FastAPI way

```python
@app.post("/create-user")
def create_user():
    return {"message": "User created"}
```

## DRF way

### 1. First create the view

```python
# views.py

from rest_framework.views import APIView
from rest_framework.response import Response

class CreateUserView(APIView):

    def post(self, request):
        return Response({
            "message": "User created"
        })
```

Here:

```python
def post(self, request):
```

means this view handles **POST** requests.

---

### 2. Then connect URL in `urls.py`

```python
# urls.py

from django.urls import path
from .views import CreateUserView

urlpatterns = [
    path("create-user/", CreateUserView.as_view()),
]
```

Now your endpoint is:

```text
POST /create-user/
```

## Main difference

FastAPI:

```python
@app.post("/create-user")
def create_user():
```

DRF:

```python
# views.py
class CreateUserView(APIView):
    def post(self, request):
        ...
```

```python
# urls.py
path("create-user/", CreateUserView.as_view())
```

## Easy memory

In FastAPI:

```text
URL + method are in decorator
```

In DRF:

```text
HTTP method is in view: get(), post(), put(), delete()
URL is in urls.py: path("create-user/", ...)
```

So DRF separates them:

```text
views.py = what should happen?
urls.py = on which URL should it happen?
```

Example:

```python
class UserView(APIView):

    def get(self, request):
        return Response({"message": "Get users"})

    def post(self, request):
        return Response({"message": "Create user"})
```

```python
urlpatterns = [
    path("users/", UserView.as_view()),
]
```

Now:

```text
GET  /users/  -> def get()
POST /users/  -> def post()
```

That is the key idea.




















Yes. Here are **all DRF View concepts in one place**, compared with **FastAPI**.

# 8. View with POST: Input Data

DRF:

```python
class TodoView(APIView):

    def post(self, request):
        serializer = TodoSerializer(data=request.data)

        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data)

        return Response(serializer.errors)
```

FastAPI version:

```python
@app.post("/todos/")
def create_todo(todo: TodoCreate):
    new_todo = Todo(
        title=todo.title,
        completed=todo.completed
    )

    db.add(new_todo)
    db.commit()
    db.refresh(new_todo)

    return new_todo
```

Important DRF part:

```python
serializer = TodoSerializer(data=request.data)
```

means:

```text
Validate incoming JSON.
```

Then:

```python
serializer.is_valid()
```

means:

```text
Check if data is correct.
```

Then:

```python
serializer.save()
```

means:

```text
Create new database row.
```

# 10. Full DRF View Example

```python
from rest_framework.views import APIView
from rest_framework.response import Response
from .models import Todo
from .serializers import TodoSerializer

class TodoView(APIView):

    def get(self, request):
        todos = Todo.objects.all()
        serializer = TodoSerializer(todos, many=True)
        return Response(serializer.data)

    def post(self, request):
        serializer = TodoSerializer(data=request.data)

        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data)

        return Response(serializer.errors)
```

And URL:

```python
from django.urls import path
from .views import TodoView

urlpatterns = [
    path("todos/", TodoView.as_view()),
]
```

Now these endpoints work:

```text
GET  /todos/  -> get all todos
POST /todos/  -> create todo
```

# Final Mental Map

| Concept        | FastAPI                | DRF                                  |
| -------------- | ---------------------- | ------------------------------------ |
| Endpoint logic | function               | view class                           |
| URL path       | `@app.get("/todos/")`  | `path("todos/", TodoView.as_view())` |
| GET request    | `@app.get()`           | `def get()`                          |
| POST request   | `@app.post()`          | `def post()`                         |
| Request body   | Pydantic parameter     | `request.data`                       |
| Validation     | Pydantic model         | Serializer                           |
| Database query | `db.query(Todo).all()` | `Todo.objects.all()`                 |
| Response       | `return dict`          | `return Response(dict)`              |

The most important idea:

```text
DRF View = place where API request is handled.

views.py = what happens
urls.py = where it happens
serializer = validates input and converts output
model = database table
```

So this DRF code:

```python
class TodoView(APIView):

    def get(self, request):
        todos = Todo.objects.all()
        serializer = TodoSerializer(todos, many=True)
        return Response(serializer.data)

    def post(self, request):
        serializer = TodoSerializer(data=request.data)

        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data)

        return Response(serializer.errors)
```

means:

```text
GET request:
database -> serializer -> response

POST request:
request data -> serializer validation -> database save -> response
```
